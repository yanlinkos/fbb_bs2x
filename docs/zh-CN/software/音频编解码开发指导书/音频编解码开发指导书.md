# Overview<a name="ZH-CN_TOPIC_0000001750642884"></a>

BS2XV100 provides developers with development and application interfaces for audio codec functionality through APIs (Application Programming Interfaces), including Audio Encoder and Audio Decoder.

The function descriptions of each component are as follows:

-   Audio Encoder: The audio encoder component, primarily provides encoding functionality for sbc, msbc, opus, and l2hc audio formats.
-   Audio Decoder: The audio decoder component, primarily decodes sbc, msbc, opus, and l2hc format bitstreams encoded by the Audio Encoder.

>![](public_sys-resources/icon-note.gif) **Description:** 
>This document describes the basic flow and API interface descriptions of each module function.

# Audio Encoder<a name="ZH-CN_TOPIC_0000001797563673"></a>




## Overview<a name="ZH-CN_TOPIC_0000001797602677"></a>

Audio Encoder primarily provides audio encoding functionality. Supported specifications include:

-   MSBC：16k
-   SBC：16k、48k
-   opus：16k、48k
-   l2hc：16k、48k

Data is collected by the MIC (AMIC/DMIC), processed by the PDM module and sent to the Audio module for encoding by the Audio Encoder.

## Development Flow<a name="ZH-CN_TOPIC_0000001797602681"></a>

**Usage Scenarios<a name="section775mcpsimp"></a>**

When the device acts as a transmitter and requires audio functionality, the Audio Encoder provides audio encoding functionality.

**Parameters and Data Structures<a name="section1317564152619"></a>**

This section mainly introduces the data structures involved in encoding.

1.  open param: Common parameters, the struct used for passing parameters during initialization in [Table 1](#_table213321716161).

```
ha_codec_enc_param {
    bool interleaved; /* Decoding deinterleave mode */
    uint32_t channels; /* Number of channels */
    int32_t bit_depth; /* Bit depth */
    uint32_t sample_rate; /* Sample rate */
    uint32_t samples_per_frame; /* Number of samples per frame */
    void *private_data; /* Encoder private parameters */
    uint32_t private_data_size; /* Decoder private parameter size */
}
```

2.  in_pkt: Encoder input buf, the struct used as encoding input in [Table 1](#_table213321716161).

```
ha_codec_enc_in_packet {
    int64_t pts; /* Used for audio synchronization; reserved parameter, currently unused */
    uint8_t *data; /* Input data pointer */
    uint32_t size; /* Input data size */
}
```

3.  out_pkt: Encoder output buf, the struct used as encoding output in [Table 1](#_table213321716161).

```
ha_codec_enc_out_packet {
    int32_t *bits_out_buf; /* Encoder output buffer */
    uint32_t bits_out_buf_size; /* Encoder output buffer size */
    uint32_t bits_out_bytes; /* Encoded data frame size, in bytes */
    uint32_t bit_rate; /* Bit rate */
}
```

4.  send_cmd: Command field, the cmd command word in [Table 1](#_table213321716161).

ACODEC_PRIVATE_PARAM_GET_CMD  0xFFFF100C Get codec private parameters

ACODEC_IN_FRAME_SIZE_GET_CMD  0xFFFF100D Get encoding input data size

ACODEC_OUT_FRAME_SIZE_GET_CMD  0xFFFF100E Get encoding output data size

ACODEC_SET_PLC_OFF_THR_CMD  0xFFFF1010 Set maximum PLC frame count, only available for sbc decoding

ACODEC_GET_PLC_OFF_THR_CMD  0xFFFF1011  Get current maximum PLC frame count, only available for sbc decoding

**Development Flow<a name="section904mcpsimp"></a>**

BS2X supports multi-specification encoders, with the encoder call interfaces abstracted as overlay_enc_entry, and after dereferencing, the interface return value corresponds to elements that are encoder instances, as shown in [Table 1](#_table213321716161).

The typical development flow for Audio Encoder is as follows.

**Server Node：**

1.  Call overlay_enc_entry()->init (parameters as shown in [Table 1](#_table213321716161)) to complete encoder initialization.
2.  Call overlay_enc_entry()->get_max_bits_out_size (parameters as shown in [Table 1](#_table213321716161)) to get the output buffer size required by the encoder, used to determine whether the reserved space in the current system meets the requirements.
3.  Call overlay_enc_entry()->encode_frame (parameters as shown in [Table 1](#_table213321716161)) to encode the input data. The return value can be used to determine whether the encoding was successful. If AUDIO_SUCCESS is returned, it indicates successful encoding, the data pointer of the in_pkt parameter will be offset by one frame of PCM data, and the size of the in_pkt parameter will be reduced by the amount of PCM data consumed by encoding. The encoded output bitstream is written to the space pointed to by the bits_out_buf pointer of the out_pkt parameter, and the bits_out_bytes variable of the out_pkt parameter is refreshed to the data size of the encoded output bit rate. If the encoding interface does not return AUDIO_SUCCESS, the failure type can be determined based on the error codes in [Error Codes](错误码.md). If encoding fails, the data in in_pkt is not consumed.
4.  Continuously call overlay_enc_entry()->encode_frame until all input buffer data is processed and no more data is sent externally, and encoding is complete.
5.  Call overlay_enc_entry()->deinit (parameters as shown in [Table 1](#_table213321716161)) to destroy the encoder.

**Sample Pseudocode<a name="section128586715157"></a>**

```
extern void *overlay_enc_entry(void);
int main()
{
    Set the open_param parameter
    overlay_enc_entry()->init /* Initialize */

    overlay_enc_entry()->get_max_bits_out_size /* Get the required output buffer size */
    if (buffer size is insufficient)
    overlay_enc_entry()->deinit; /* Destroy the encoder */

    while (encoding is not complete)
    overlay_enc_entry()->encode_frame;
    if (encoding succeeds)
    Update the input data pointer and size based on out_buf;
    else
    Handle based on the error code;
    end if

    if (encoding is complete)
    break;

    overlay_enc_entry()->deinit /* Encoding complete, destroy the encoder */
}
```
